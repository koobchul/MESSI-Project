# SHOT 선택 편향 보정 비교

## 확인한 결과와 제한

전체 경기 4개는 모두 regulation_complete, 5400초로 완료됐다.
기존 BC는 seed 2001/2002에서 0–12, 0–7, 실제 슈팅 0/0이었다.
수정 BC는 0–25, 0–9, 실제 슈팅 1/10이었다. 수정 모델의 경기 성능 향상은 입증되지 않았다.

수정 학습의 SHOT 라벨은 491,520개 중 22개(0.00448%)인데 재표집 확률은 5%였다.
SHOT의 표집 비중이 약 1,117배 커졌다. 기존 검증 gate는 SHOT recall을 사용하고 precision을 검사하지 않았다.
검증 seed 22에서 SHOT 예측 184개 중 교사 SHOT과 일치한 것은 5개(precision 2.72%)였다.
교사 라벨은 절대적인 최적 행동의 정답이 아니며 이 수치만으로 실제 슈팅의 적법성을 판단할 수 없다.
재표집, 학습 분포와 실제 플레이 분포의 차이가 과다 선택에 기여할 가능성이 있다.
이것이 소유 실패나 모든 실점의 원인으로 확정된 것은 아니다.

## 이번에 하는 일

현재 수정 가중치에서 SHOT logit bias만 0, -3.5, -7.0으로 비교한다.
자연 SHOT 빈도와 재표집 빈도의 이진 log-odds 차이는 약 -7.07이다.
-7은 이를 근사한 강한 보정이고 -3.5는 완화한 보정이다.
MOVE 내부의 near/far 재표집과 공유 회귀 손실 때문에 이 보정이 정확한 확률 복원을 보장하지는 않는다.
샘플 비율을 사후 보정하는 통제 실험이며 추가 학습이나 완성된 공격 정책이 아니다.

이동, 몸 방향, 공 제어의 연속 출력 파라미터와 backbone은 변경하지 않는다.
단, intent가 바뀌면 같은 연속 출력의 환경 내 해석과 다음 관측이 바뀌므로 실제 궤적은 달라질 수 있다.
기존 환경과 retouch guard를 사용한다. 새 거리 마스크나 교사 행동 대체는 없다.
원본 체크포인트 SHA256을 확인하고 별도 출력에만 후보를 저장한다.

1. 새 seed 3000,3001에서 세 후보를 각각 6,400스텝 평가한다(총 6개 probe).
2. 원본 수정 모델 대비 정상 소유 합계 증가, 실제 슈팅 발사 합계 1 이상,
   슈팅 요청 합계 50% 이하, 득점 합계 비감소, 실점 합계 비증가와 각 경기 실점 증가 1 이하를 모두 요구한다.
3. 통과한 후보가 있으면 실점 합계, 득점 합계, 정상 소유 합계 순으로 선택한다.
4. 선택 후보만 새 seed 3002,3003 전체 경기를 실행한다. 새 전체 경기에는 원본 대조군이 없으므로
   이 두 경기만으로 상대적인 성능 향상을 주장하지 않는다.
5. 통과 후보가 없으면 지표를 저장하고 종료한다. 어떤 경우에도 원본을 덮어쓰거나 최종 모델로 자동 승격하지 않는다.

위 기준은 비용 제한을 위한 공학적 기준이지 통계적 성능 보장이 아니다.

## 로컬 검증

- 실제 업로드 가중치에서 오직 SHOT bias 한 항목만 바뀌는지 확인 통과.
- 원본의 모든 나머지 파라미터 일치, 같은 입력의 후보 export 일치 확인.
- 원본의 validation/gate 통과 표시가 새 후보에 잘못 남지 않도록 제거 확인.
- 선택 기준이 실제 발사 0 또는 실점 악화 후보를 거부하는지 확인.
- Python 문법 검사, sbatch bash 문법 검사 통과.
- 기존 seed 10의 40,960개 학습 예시를 NumPy MLP forward로 비교(retouch guard 적용 전):

| SHOT bias 변화 | SHOT 예측 수 | 교사 SHOT 일치 | 교사와 다른 SHOT 예측 |
|---|---:|---:|---:|
| 0 | 38 | 1 | 37 |
| -3.5 | 1 | 1 | 0 |
| -7.0 | 0 | 0 | 0 |

이 데이터는 학습에 사용된 데이터이며 SHOT 라벨이 1개뿐이다. 일반화 성능의 증거가 아니다.
로컬에서 GPU 실제 경기 비교는 수행하지 않았다. 사용자의 배치 실행으로 검증한다.
강한 보정은 슈팅 자체를 없앨 수 있으므로 실제 발사가 없는 후보를 선택하지 않는다.

## 실행

기존 패치가 설치된 MESSI 폴더, conda messi 환경에서:

```bash
tar -xzf shot_calibration_patch.tar.gz
sbatch shot_calibration_patch/run.sbatch
```

설치 스크립트는 필요 없다. 기존 project 파일을 수정하지 않는다.
최대 2시간 GPU를 요청한다. 미통과 시 전체 경기를 건너뛰므로 일찍 끝날 수 있다.
경기 상태는 기존 evaluator가 128스텝마다 저장한다.
시간 제한으로 중단되면 같은 sbatch 명령으로 재개한다. 완료된 경기에는 소규모 초기화 비용이 다시 든다.
평가 프로그램 자체의 오류로 중단됐으면 재제출 전에 로그를 확인한다.

종료 후 다음 파일을 업로드한다:
`project/experiments/shot_calibration_seed0/calibration_results.tar.gz`

로그:
`tail -f shot_calibration-작업번호.log`

정상 종료 및 Python 예외에서는 결과가 자동 압축된다. 강제 종료로 압축파일이 없거나 불완전하면:

```bash
tar -czf calibration_results_manual.tar.gz --exclude='*.pkl' --exclude='*.tar.gz' --exclude='run.lock' \
  -C project/experiments shot_calibration_seed0
```

같은 출력 폴더에 동시 작업은 flock으로 차단한다.
